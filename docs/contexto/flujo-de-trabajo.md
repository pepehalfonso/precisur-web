# Flujo de trabajo — Web Precisur

## Antes de modificar código

1. Leer CLAUDE.md.
2. Leer proyecto.md.
3. Leer narrativa.md.
4. Determinar qué parte de la historia está construyendo.
5. Revisar decisiones.md.
6. No inventar capacidades inexistentes.

---

# Para crear una sección

Antes de implementar responder:

### Pregunta

¿Qué pregunta debe responder esta sección?

### Objetivo

¿Qué debe entender el visitante después?

### Emoción

¿Qué debe sentir?

### Evidencia

¿Qué información respalda el mensaje?

### Visual

¿Cuál es la mejor representación?

# Orden de construcción

## Fase 1 — Fundaciones

* setup del proyecto
* sistema tipográfico
* tokens visuales
* responsive
* layout global

## Fase 2 — Narrativa

* Hero
* desafío
* problema
* Precisur
* ecosistema

## Fase 3 — Tecnología

* simulación
* partículas
* mapas
* arquitectura
* evidencia

## Fase 4 — Institucional

* validación experimental
* oportunidad
* colaboración
* cierre

## Fase 5 — Pulido

* animaciones
* rendimiento
* accesibilidad
* SEO
* revisión de claims

# Antes de dar algo por terminado

* [ ] La sección funciona en móvil.
* [ ] La sección funciona en desktop.
* [ ] La animación tiene propósito.
* [ ] No existen afirmaciones científicas falsas.
* [ ] La narrativa continúa correctamente.
* [ ] No se usan componentes genéricos innecesarios.
* [ ] El rendimiento es aceptable.
* [ ] No hay elementos decorativos que distraigan.
* [ ] El texto es institucional y comprensible.
* [ ] La sección ayuda a responder por qué Precisur merece apoyo.

---

# Regla de desarrollo

No intentar construir toda la web en una sola iteración.

Trabajar por fases.

Después de cada fase:

1. revisar
2. corregir
3. validar responsive
4. validar narrativa
5. continuar
