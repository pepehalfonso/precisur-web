# Arquitectura — Web Institucional Precisur

## En una frase

Experiencia web inmersiva diseñada para explicar un problema agrícola complejo, demostrar una base tecnológica real y presentar una oportunidad de colaboración institucional para impulsar agricultura de precisión desarrollada en Uruguay.

---

# HERO

Objetivo:

Generar curiosidad.

No explicar todo inmediatamente.

Concepto:

Un paisaje agrícola abstracto combinado con:

* partículas en movimiento
* vectores de viento
* líneas topográficas
* datos meteorológicos
* geometría
* una sensación de sistema vivo

Texto sugerido:

PRECISUR

TECNOLOGÍA PARA ENTENDER
LO QUE OCURRE ANTES DE APLICAR.

Subtexto:

Simulación. Meteorología. Geografía. Ingeniería.

---

# Sección: El desafío

Explicar que una aplicación agrícola ocurre dentro de un sistema dinámico.

Visual:

Una gota suspendida.

Alrededor aparecen fuerzas:

* viento
* gravedad
* evaporación
* turbulencia

El usuario debe entender visualmente que una gota no sigue una trayectoria trivial.

---

# Sección: El problema invisible

Visualización interactiva.

Slider:

VIENTO

El usuario aumenta la intensidad.

La nube de partículas cambia.

Después:

ALTURA

La trayectoria cambia.

Después:

TAMAÑO DE GOTA

El comportamiento cambia.

Mensaje:

> Pequeñas decisiones pueden producir grandes diferencias espaciales.

IMPORTANTE:

Esta visualización debe ser educativa.

No afirmar precisión experimental.

# Sección: Simulación

Esta debe ser una de las secciones más impactantes.

Mostrar:

* lote
* drone
* trayectoria
* emisión
* viento
* partículas
* zonas sensibles
* concentración

La animación debe dar la sensación de estar observando un sistema técnico real.

No utilizar GIFs genéricos.

---

# Sección: Evidencia

Aquí aparece la ingeniería.

Visual:

Un contador progresivo.

934
PRUEBAS AUTOMATIZADAS

0
ERRORES DE ANÁLISIS

1
MOTOR FÍSICO CANÓNICO

Luego una arquitectura visual.

No mostrar números como marketing vacío.

Cada métrica debe tener explicación contextual.

---

# Sección: Ingeniería bajo presión

Esta sección debe ser inesperada.

Título:

¿QUÉ PASA CUANDO EL SISTEMA FALLA?

Mostrar un timeline:

BUG DETECTADO
↓
CAUSA ENCONTRADA
↓
CORRECCIÓN
↓
PRUEBA DE REGRESIÓN
↓
VALIDACIÓN

Mostrar algunos ejemplos reales:

* gravedad invertida
* partículas fuera del mapa
* conflicto entre motores
* errores de sincronización

Mensaje:

> La ingeniería no consiste en escribir código que parece funcionar.
>
> Consiste en intentar romperlo antes de confiar en él.

Esta sección puede generar mucha credibilidad institucional.

# Sección: Smart Spray

Explicar visualmente:

LOTE
↓
IDENTIFICACIÓN DE BORDES SENSIBLES
↓
SIMULACIÓN DE ESCENARIOS
↓
COMPARACIÓN
↓

Nunca venderlo como autonomía total.

Presentarlo como:

Sistema experimental de análisis de escenarios.
