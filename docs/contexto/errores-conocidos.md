# Errores conocidos y advertencias — Web Precisur

## Confundir pruebas de software con validación experimental

* Pasa cuando: se utilizan métricas de tests para afirmar precisión científica.
* Causa: confusión entre verificación computacional y validación experimental.
* Solución: diferenciar claramente ambos conceptos.

---

## Convertir Precisur en una empresa ficticiamente madura

* Pasa cuando: se presentan todos los módulos como productos comerciales terminados.
* Causa: intentar aumentar credibilidad mediante exageración.
* Solución: explicar el estado tecnológico real.

---

## Abusar del lenguaje de IA

* Pasa cuando: aparecen frases como "revolucionamos la agricultura con inteligencia artificial".
* Causa: lenguaje genérico de marketing.
* Solución: describir tecnologías concretas.

---

## Usar dashboards falsos

* Pasa cuando: se agregan gráficos con números arbitrarios únicamente para decorar.
* Causa: intentar hacer la web más tecnológica.
* Solución: utilizar datos reales, simulados claramente etiquetados o visualizaciones conceptuales.

---

## Demasiadas tarjetas

* Pasa cuando: cada concepto se convierte en una card.
* Causa: patrón automático de diseño web moderno.
* Solución: construir experiencias visuales más editoriales y narrativas.

---

## Animación sin significado

* Pasa cuando: partículas, gráficos o efectos se mueven únicamente por estética.
* Causa: confundir movimiento con experiencia.
* Solución: cada animación debe representar un fenómeno o transición conceptual.

---

## Complejidad técnica incomprensible

* Pasa cuando: se muestran ecuaciones y arquitectura sin contexto.
* Causa: intentar impresionar mediante complejidad.
* Solución: traducir ingeniería compleja a visualizaciones comprensibles.

---

## Esconder las limitaciones

* Pasa cuando: la web evita mencionar validación experimental pendiente.
* Causa: miedo a parecer menos madura.
* Solución: convertir la necesidad de validación en una oportunidad de colaboración.

---

# Cosas que NO deben "arreglarse"

* El sistema no necesita parecer una startup SaaS.
* No todas las secciones necesitan botones.
* No toda la información debe entrar en tarjetas.
* No se debe prometer autonomía total.
* No se debe afirmar que el modelo representa exactamente la realidad.
* La complejidad científica debe existir, pero explicarse progresivamente.
